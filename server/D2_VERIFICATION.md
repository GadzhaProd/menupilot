# D2 — безопасность и конкурентность

Проверено 2026-10-21, macOS, Node 25.8.1. Рабочая ветка `bb/astra-d2-thr_z48ngm95xt`.

## Реализация

- Одноразовый 256-битный секрет запуска в `launch-secret` (0600), адрес с фрагментом `#k=`. Внешний login.js удаляет фрагмент через replaceState до JSON-обмена и затем заменяет страницу адресом без секрета. Успешный обмен меняет секрет до ответа. Поддержан переход из уже открытой страницы входа (hashchange).
- Cookie HttpOnly, SameSite=Strict, Path=/menupilot/, имя включает порт. Без cookie — только инструкция EN/NL. HTML приложения и JSON-конфиг защищены cookie; UI token отсутствует в HTML. `open-url` читает секрет из приватного файла и проверяет экземпляр сервера. CLI token остаётся отдельным файлом 0600.
- Точный Host, отклонение foreign/null Origin, UI POST только с точным Origin; CLI POST может не иметь Origin, но raw write по-прежнему запрещён.
- Существующий inline bootstrap темы/языка из доверенного dist сервер выносит в отдельный same-origin JS; статическая версия не меняется.
- CSP без inline scripts, frame-ancestors none, DENY, nosniff, no-referrer, no-store для HTML/API/config. Inline styles разрешены для существующего UI.
- JSON body ≤15 100 000 UTF-8 байтов, login ≤1024. Заголовки 10 с, тело 15 с, keep-alive 5 с, до 32 соединений, 100 запросов/соединение. Явные таймеры дополняют встроенные таймауты Node.
- Диагностический журнал: только время, фиксированные события, уровень и HTTP status; три файла всего до 1 MiB каждый, уровень MENUPILOT_LOG_LEVEL. Документ и секреты не передаются logger вообще.
- Удаление неиспользуемого ингредиента уже сохраняло снимок. Теперь journal дополнен описанием, ID и количеством удалённых цен. Это необязательные метаданные аудита, без смены схемы SQLite/документа; снимок и запись журнала остаются в одной транзакции.

## Фактические проверки

`VITEST_MAX_WORKERS=2 npm run check`: typecheck, core, UI, server, mutations и build.
Core: 195 passed; UI: 34 files / 387 passed; server: 56 passed, 0 failed;
мутации: 13 CAUGHT; production build завершён успешно.

`npm run test:e2e`: `23 passed (12.5s)`.

`npm run test:e2e:local`: `2 passed (9.3s)` — desktop и 375 px, вход по секрету,
две независимые browser contexts с общей cookie, CAS-конфликт конкурирующих записей,
черновик при рестарте, сохранность истории цен, импорт с предпросмотром и отсутствие ошибок CSP.

`git diff --check`: без ошибок.

Проверки процессов выполнялись вне sandbox: macOS inspection для lock требует этого.
Новые concurrency-тесты запускают настоящий сервер и два IPC-клиента в отдельных
OS-процессах. UI пишет одновременно с CLI-чтением; после пятой записи SIGKILL и
повтор после рестарта не создают вторую запись. Отдельный HTTP proxy действительно
обрывает клиентский сокет после получения commit-ответа от сервера; повтор после
рестарта возвращает исходную квитанцию и один снимок. Два клиента с общей cookie
получают тот же конфиг, но конкурирующие записи всё равно проверяются по CAS.

Атаки в test:server: чужой Host, rebinding hostname через TCP к loopback, foreign/null
Origin для чтения и записи, отсутствие токена/cookie, поддельная cookie, text/plain
CSRF, GET write, oversized Content-Length и chunked body, slow headers/body,
connection cap, traversal/symlink, framing headers, секреты в логах и повтор ключа.

Мутации в отдельной временной копии (все пойманы): CAS identity, append-only
transition, receipt deduplication, lock ownership, cookie gate config, cookie gate
HTML, foreign Origin, missing Origin, one-time secret rotation, frame-ancestors,
streaming body budget, Host, token. Мутации входят в npm test/check и существующий CI.

Воспроизведённые и исправленные проблемы во время разработки:
- Исходная версия: HTML без cookie отдавал приложение, foreign Origin проходил,
  slow headers не закрывались в проверяемый срок; новые тесты сначала падали.
- Переход по фрагменту с уже открытой страницы не перезапускал login.js: ручное
  воспроизведение, регрессия с исполнением script в VM, обработчик hashchange.
- Локальный mobile e2e проверял наличие меню до завершения нового async config:
  добавлено ожидание local-mode, оба проекта прошли повторно.
- Параллельные независимые тестовые файлы могли запускать несколько Vite builds
  в один dist (ENOTEMPTY). test:server запускает файлы последовательно; внутри
  тестов серверы/клиенты остаются конкурентными. Одновременная сборка этого checkout
  вручную для разных dataDir всё ещё не сериализуется (существующее ограничение D1).

## Модель угроз и ограничения

Защищено: неавторизованное чтение UI-токена через общий loopback; hostile websites,
CSRF, DNS rebinding, clickjacking; ограничены размеры/время/соединения; потерянный
ответ и конкурирующие сохранения не обходят квитанции/CAS.

Не защищено: процессы того же OS user, читающие 0600/SQLite, root, расширения с
доступом к странице, скомпрометированный браузер. Cookie не изолируют порты:
если посетить вредоносный loopback service по совпадающему пути в том же профиле,
он может получить cookie. Секрет намеренно выводится в терминал; crash браузера до
replaceState может оставить исходный адрес, использованный секрет уже недействителен.
Это не доказательство согласия человека и не гарантия доступности при локальном DoS.

Не проверялись здесь Linux/Node 24.15.0, реальная потеря питания, заполненный диск и
backup failures (D3). SIGKILL не является испытанием потери питания. История остаётся
ограниченной 32 снимками/64 MiB. Предупреждения сборки о chunk >500 kB и Node/Vitest
о localstorage-file сохраняются; ошибок проверок нет.
