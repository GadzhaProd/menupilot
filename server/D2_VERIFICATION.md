# D2 — исправления после ревью

Проверка: macOS, Node 25.8.1, 2026-10-22. Дополняет первоначальные коммиты D2;
замечания ревью `thr_4m6iyegm57` проверены воспроизведением и мутациями.

## Что исправлено

1. Dist загружается в память до listen. Удаление файла на диске при работающем
   сервере возвращает прежний снимок (200), сервер остаётся жив. JSON сериализуется
   до writeHead. Error handler проверяет headersSent до любого setHeader; ошибки
   error-response и отклонения request Promise перехватываются. Регрессия проверяет
   отдельный процесс, исчезнувший asset и ошибку сериализации ответа.
2. Cookie открывает только HTML без секретов. POST session возвращает отдельный
   bearer token на сеанс; login.js сохраняет его в sessionStorage, изолированный
   по origin с портом. Конфиг и API требуют Authorization, конфиг токен не возвращает.
   Реальный второй HTTP-сервер с перехваченной cookie и подставленным Origin получает
   401 на конфиг и запись. Сеансы: 10 ч абсолютно, 1 ч простоя, максимум 128.
3. Полная CSP проверяется точным сравнением, включая 302/login.js/bootstrap JS.
   Добавлены CORP и COOP same-origin. Изменение порядка unsafe-inline, разрешение
   https:/wildcard, удаление base-uri/form-action и isolation headers ловятся мутациями.
4. Ссылка живёт 15 минут, одноразовая. Каждый open-url по CLI token выпускает новую;
   --revoke-sessions дополнительно отзывает все токены/cookie. CLI не выдаёт ссылку
   по одному чтению файла и проверяет экземпляр сервера. Сроки проверены управляемыми
   часами, CLI — настоящими дочерними процессами.
5. Логи по умолчанию warn: успешный опрос не вытесняет отказы. Причины — строго
   host/origin/sign-in/token/size; свободный текст, URLs, cookie, токены и документы
   не передаются в диагностический журнал. Три файла по 1 MiB, права 0600.
6. Login body 1024 bytes, duplicate cookie, maxRequestsPerSocket=100, POST статики
   405 и keep-alive проверяются поведением и мутациями. Keep-alive тест учитывает
   дополнительный секундный socket buffer Node.
7. README/03 прямо описывают локальный DoS и сохранение следов адреса в browser
   history/sync; replaceState не обещает стирание истории посещений. Документационные
   проверки и две мутации не позволяют удалить эти оговорки незаметно.
8. localhost на URL страницы возвращает короткую HTML-инструкцию EN/NL использовать
   127.0.0.1, без данных. В журнале удаления ингредиента теперь есть имя вместе с ID,
   числом цен и снимком предшествующего документа.

## Модель угроз

Защищено: cookie, перехваченная другим loopback-портом, не превращается в токен
или API-доступ. Без секрета/токена нет чтения данных и записи. Host/Origin/CSP,
лимиты и атомарные квитанции/CAS остаются в силе; запись после потерянного ответа
не дублируется. Пересборка файлов не обрушает работающий сервер.

**Утечка UI token даёт полный доступ чтения/записи до истечения или отзыва.**
Origin не препятствует native client подставить заголовок. Процесс того же OS user
читает файлы 0600 и SQLite; root, расширения и скомпрометированный браузер не изолированы.
Секреты видны в терминале; ссылки могут остаться в истории браузера/Sync, но имеют
срок и одноразовость. Это не доказательство согласия человека. Локальный DoS
постоянным занятием 32 соединений остаётся возможен. Закрытие вкладки обычно очищает
sessionStorage, но восстановление браузерного сеанса может его вернуть.

Не проверены Linux/Node 24.15.0, потеря питания, заполненный диск, backup failures
(D3). SIGKILL — не испытание потери питания. Сборка одного checkout в разных
процессах по-прежнему не сериализована; запуск при незавершённой сборке не покрыт
этим исправлением, но уже работающий сервер обслуживает свой неизменный снимок.
