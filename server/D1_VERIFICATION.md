# D1 — отчёт реализации и проверки, 2026-10-21

Статус: замечания ревью D1 исправлены; готово координатору (не готовность D2–D6).

## Что сделано

- Сервер `npm start`, Node runtime check, сборка по отпечатку входных файлов,
  loopback 127.0.0.1, production-путь `/menupilot/`, остановка по SIGINT/SIGTERM.
- Канонический внешний каталог данных, атомарный lock/instanceId, безопасный
  отказ второму серверу, восстановление после мёртвого владельца.
- SQLite: отдельная версия структуры, WAL/FULL, транзакционные CAS,
  история, неизменные квитанции opId, журнал с источником и бюджеты хранения.
- Серверная валидация документа и обычного перехода, отдельные замены
  import/reset/restore; чтение повреждённого документа даёт отказ.
- HTTP: Host, токен всего API, отдельные UI/CLI токены, CLI файл 0600,
  JSON/лимит тела, whitelist маршрутов и файлов сборки, безопасный no-store HTML.
  CLI-токен не может обращаться к сырому write API.
- HTTP-адаптер, ограниченные повторы, beforeReplace, подписка опросом,
  сохранность черновиков при недоступности/перезапуске сервера, без browser fallback.
- EN/NL-индикатор пути, локальные тексты Data/history, импорт с предпросмотром
  количества сущностей и заменой без объединения.

## Мутационные проверки

`node test/server/mutations.js` работает в временной копии исходников, не меняет
checkout. Все шесть намеренных поломок обнаружены соответствующими тестами:

```text
CAUGHT: CAS identity
CAUGHT: append-only transition
CAUGHT: receipt deduplication
CAUGHT: lock ownership
CAUGHT: Host check
CAUGHT: token check
```

Тест отказа записи использует SQLite trigger RAISE(ABORT) после изменения
основного документа: откатываются document/history/journal/ops, затем повтор
успешен. Это не тест физического ENOSPC/сбоя питания; они остаются D3.

## Для владельца — шесть пунктов

1. **Что сделано:** MenuPilot запускается локально, сохраняет данные в SQLite
   вне папки проекта, использует прежний интерфейс.
2. **Зачем:** браузер больше не является единственным местом хранения локальной
   версии; данные остаются после остановки сервера и обновления проекта.
3. **Как работает:** один сервер принимает изменения, проверяет их и сохраняет
   целиком. Повтор потерянного ответа не добавляет цену второй раз. Второй сервер
   не получает право записи в ту же папку.
4. **Как проверить:** установить Node 24.15.0 LTS, выполнить `npm ci`, `npm start`,
   открыть напечатанный адрес. В Ingredients создать ингредиент и новую цену.
   Остановить Ctrl+C, снова `npm start`, обновить страницу, проверить Price history.
   Для переноса — Export в браузерной версии, Data → Import локально, проверить
   предпросмотр и подтвердить. Сохранить исходный файл.
5. **Тесты:** 195 core + 387 UI + 46 server, 23 прежних E2E + 2 локальных E2E;
   typecheck и production build успешны, шесть мутаций пойманы.
6. **Что ещё не сделано:** D2 — Origin/CSP и независимый аудит безопасности;
   D3 — автоматические независимые копии, restore/аварийные испытания;
   D4 — CLI чтения/doctor; D5 — предложения цен с подтверждением владельца;
   D6 — установка, обновление и документация агента. Windows вне первой версии.
   Пока регулярно используйте Export.

## Замечания для ревью

- Протокол подробно описан в 03_ARCHITECTURE, раздел «Локальный режим D1».
  В ответе актуальный документ отделён от первоначальной квитанции. Проверка
  квитанции предшествует отказу устаревшего CAS — иначе повтор после commit
  получал бы конфликт. Хеш связывает неизменную логическую команду и source;
  наблюдаемый expectedDocumentId исключён из хеша для повтора после повторного
  открытия адаптера, но обязателен в CAS каждой новой операции.
- Lock recovery сериализован отдельной служебной SQLite БД, основной файл
  данных открывается только после захвата lock. В lock есть время старта и boot-id;
  PID reuse, старый пустой lock и старый guard восстанавливаются автоматически.
  Живой процесс без подтверждённого HTTP instanceId сохраняет блокировку.
  Реальные одновременные стартёры проверены, включая старый guard.
  Полноценный doctor остаётся D6.
- Это защита от случайных ошибок и сторонних сайтов в рамках D1, не изоляция от
  другого процесса того же пользователя или расширения с доступом к странице.
- Автосборка разных checkout, указывающих на одну папку dist, не поддерживается;
  каждый checkout владеет своей сборкой. Tests используют отдельные каталоги
  данных; локальные E2E имеют отдельный outputDir от браузерных E2E.
- Зависимости и src/calc не изменялись. По разрешению координатора .github
  изменён только для закрепления Node 24.15.0; корневое поле engines lockfile
  синхронизировано через npm install --package-lock-only (других изменений нет).
- Исправлены literal-$ в HTML, неверный history/read (400), ранний Content-Length
  и потоковый лимит (413 + Connection: close), канонический reset EN/NL/empty.
  Проверены обходы путей и symlink вне dist. На каждый пункт есть регрессия.
- Полные повторные логи: thread-storage/thr_wvvsd9hcqp/d1/review-*.log.
  Origin, доступ локальных процессов к UI-токену и политика удаления
  ингредиента вместе с его ценами оставлены для D2 по указанию координатора.
