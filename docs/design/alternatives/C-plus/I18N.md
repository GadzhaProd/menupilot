## Контракт

`type Locale = 'en' | 'nl'`; `const en` определяет тип ключей, `nl satisfies Record<TranslationKey, string>` проверяет покрытие. Runtime t(key,params) берёт готовую строку выбранного dictionary; интерполяции форматируют date/count/money заранее existing formatters. Ни regex по DOM, ни innerHTML/textContent translation, ни MutationObserver. Перевод не меняет числовое значение и не записывает форматированные деньги в document.

Точечные будущие файлы: src/ui/i18n/{en,nl,index,LocaleProvider}.ts[x]. Отдельный storage `menupilot.ui.locale.v1`, валидация en/nl, default EN для совместимости; смена языка меняет document.documentElement.lang. Исключить частичный EN fallback в NL для известных ключей (компиляция/coverage test); generic translated error для неизвестного failure, original error только в техническом логе без данных пользователя.

Локализовать validation errors, accessible names, statuses, empty states, confirmation dialogs, date/volume labels, toast и все Help navigation. Domain functions остаются чистыми; через тонкий UI adapter переводить stable failure codes, не разбирать английское message регулярками. Если код не существует, исполнитель отдельно добавляет typed result code без изменения сохранённой схемы и с regression tests. Help EN/RU не удалить; полный NL добавить отдельным typed content set с теми же section IDs.

Не склеивать label из переведённых слов: отдельные полные ключи для “Menu price incl. VAT”, “Recipe-based ingredient cost excl. VAT”, “Change vs Baseline per month”. Суммы передавать параметрами, не переводить знак или разделители вручную. NL:1.234,56; EN текущий exact formatter. UI copy review носителем NL полезен перед выпуском, но отсутствующий перевод не маскировать английской строкой.
