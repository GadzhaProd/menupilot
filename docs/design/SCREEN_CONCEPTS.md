## Dashboard — увидеть последствие, затем блюдо

**Задача.** После новой цены понять, какие блюда подорожали и что это означает
при собственной оценке месячного объёма. Основной выход — Simulate конкретного блюда.

**Первый экран.** Заголовок и Help; одна сводная полоса с суммой месячного изменения
и объяснением; компактный выбор даты; сразу начинается таблица блюд. Сумма имеет
больший вес, но не лишается подписи «Monthly impact at your volume» и оговорки
«Contribution before other costs». Подсчёт подорожавших, средний food cost и отсутствие
объёмов сохранены. Сравнение 7/30/90 дней и произвольной даты остаётся прежним.

**Строка.** Блюдо и состояние; обе menu prices с VAT-label; recipe cost before/now
в одной визуальной группе с раздельными подписями; денежная дельта и food cost points;
contribution; monthly impact и ссылка Simulate. Группирование не удаляет столбцы данных.
Оставить исходный порядок блюд: новый ranking/sort не входит в визуальный этап.

**375 px.** Краткая сводка; определение simple average в раскрытии. Каждое блюдо
сразу показывает рост cost, нынешний ingredient cost и месячное изменение. «All figures»
открывает остальные значения без перехода. Полные термины переносятся. В проверенном
мокапе начало первого блюда на y≈743 px, поэтому на 812 px видны имя и метка; действие
чуть ниже. Это измеренный результат, не обещание уместить все данные в один экран.

**Границы.** Preps отдельным списком: только recipe-based cost на единицу; без цены
меню и contribution. Подсказка Sligro, если сохранена исполнителем, остаётся справкой,
не целью или сигналом «плохо». Не придумывать график изменения цен.

## Profit Simulator — меняю слева, проверяю справа

**Задача.** Увидеть различие между реальными данными и собственными A/B/C и сохранить
нужный сценарий, не затронув рецепт. Основной выход — Save scenario, не Apply to recipe.

**Desktop.** Выбор блюда и общий объём над рабочей областью. Слева редактируется
один выбранный сценарий; справа постоянно видны Baseline и все существующие сценарии.
Буква + имя — идентичность сценария, синий столбец — выбранный; highest monthly —
отдельная текстовая оценка текущих сравнимых данных, не «лучший выбор для бизнеса».
Добавление остаётся доступно до трёх сценариев. В мокапе показано состояние с тремя,
поэтому Add scenario там отсутствует.

**Поля.** Имя, цена incl. VAT, собственный необязательный объём; ingredient overrides
и top-level quantities в раскрытиях. Сохранение/удаление/обновление baseline остаются
существующими командами. Общий объём не подменяет отдельный override; пустота означает
наследование, `0` — собственный ноль. Переключение A/B/C сохраняет локальные drafts;
не размонтировать редактор так, чтобы терять незаписанный ввод.

**375 px.** Сначала выбранный A/B/C и редактируемая цена, сразу за ними две колонки
Baseline / выбранный вариант: contribution за порцию и месяц. Затем «All figures»
с полной таблицей и все остальные поля. Desktop/mobile использует один источник
локального draft; статичный дублированный read-only input мокапа **не** инструкция
создавать два независимых состояния в React. При редактировании ingredient/quantity
мобильный summary результата должен оставаться доступен рядом (краткое повторение
у группы полей), не заставлять возвращаться к верху всей страницы.

**Состояния.** Без сценариев — краткое объяснение и Add scenario; без блюда — текущий
DishPicker. Stale baseline показывает причину, скрывает несопоставимые дельты,
предлагает явный Update baseline. Unknown/error не сравниваются как ноль. При равенстве
перечисляются все лидеры, без медалей и рекомендаций. В месячном сравнении сохраняются
исключения и причины: older prices, no sales estimate, cost unknown, cannot calculate.

## Recipe editor — состав и итог в одном поле зрения

**Задача.** Изменить настоящий рецепт и понять его стоимость до сохранения.
Явное пояснение отличает этот экран от Simulator. Save recipe сохраняет настоящие данные.

**Композиция.** Детали блюда и состав слева; справа спокойный итог draft. Строки состава
разделены линиями, одинаковые поля выровнены по колонкам. Единица рядом с количеством,
yield отдельно, строковая стоимость подписана excl. VAT. Удаление строки тише Save.
В desktop итог можно закрепить; если viewport низкий, sticky отключить.

**Dish / prep.** Тип задаётся существующим потоком, не новым toggle конверсии.
Для prep вместо menu price/VAT/portions/volume — output quantity/unit; итог на партию
и единицу выпуска. Изменение типа данных не входит в дизайн. Рядом с prep-ссылкой
показывать тип и понятное имя, не строить новый визуальный node editor.

**375 px.** Краткий итог выше формы; каждая строка состава — название на всю ширину,
ниже количество/единица, затем yield/cost. Никакой таблицы полей шире экрана.
Перед Save повторить краткий итог; клавиатура не закрывает ошибку или кнопку.
Cost unknown сообщает, где отсутствует цена, не выдаёт €0.00. Cycle/depth/invalid unit
ошибки сохраняются и объясняются текущими средствами; не скрывать их generic toast.

## Ingredients — накладная и история, без лишних действий

**Задача.** Найти ингредиент, добавить новую pack price, при необходимости проверить
историю. Main action New price видима в каждой строке; History отдельная ссылка;
Rename/Delete доступны в подписанном More. Оригинальные доступные имена содержат
название ингредиента, даже если видимая надпись короткая.

**Композиция.** Одна таблица: ingredient, pack size, pack price excl. VAT,
display-only price/kg/l/pc, last price и действия. Base unit не теряется: показать в
подробности/редакторе; исполнителю не убирать её из доступного описания ингредиента.
В мокапе шесть примеров для композиции, в продукте показывать весь нынешний список.

**Форма цены.** Сохранить существующий Radix диалог. Title с именем ингредиента,
pack size + unit, price excl. VAT и точный supplier hint, вычисленная цена/unit,
Cancel и Add price. Формы Add ingredient/Rename не превращать в настройку товара.
В HTML содержимое диалога показано inline для обзора, не для изменения production-flow.
History только чтение, newest first по существующим recordedAt/seq; цена и размер
старой упаковки остаются вместе. 375 px — одно поле на строку и собственный скролл диалога.

## Help — Read

**Задача.** Понять одно действие и безопасно вернуться к работе. Основной успех —
человек находит нужный шаг, а не нажимает большой marketing CTA.

Слева оглавление; справа текст 20/32 в меру 60–68ch. На телефоне оглавление в потоке
перед статьёй. English/Русский и Print guide сохраняются; текущие section IDs,
глубокие ссылки, фокус заголовков, back-to-contents и print CSS обязательны.
Мокап даёт только выдержку и образец кириллицы: **не заменять** существующий Help
этим сокращённым текстом. Существующие изображения инструкции потребуют обновления
после реализации дизайна, но не в этом документальном этапе.

## Матрица состояний для всех экранов

| Состояние | Представление | Проверка |
|---|---|---|
| Первый запуск | существующие demo-data + понятное пояснение | без навязанного tutorial wizard |
| Нет данных | причина + одно доступное действие Add/Create/Import | не рисовать нулевые суммы вместо отсутствия |
| Нет цены | cost unknown и причина | распространяется через prep |
| Нет объёма | «—», исключён из total | отличается от 0 |
| Загрузка Help | стабильная текстовая область, status | без вечного spinner и layout jump |
| Невалидное поле | label + field + error, aria linkage | focus первого invalid |
| Ошибка store/import | постоянное сообщение с причиной | документ на экране не заменён |
| Saved / unsaved | короткий inline status у Save | не объявлять успех до store success |
| Stale scenario | Baseline changed и Update baseline | не рисовать свежую дельту |
| Слишком длинное имя/большая сумма | перенос имени, полная сумма | никакого обрезания финансового значения |
| Keyboard/reduced motion | видимый focus, мгновенный результат | ни одного hover-only действия |
