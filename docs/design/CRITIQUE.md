## Что уже хорошо

Терминология честно отличает вклад от прибыли. Simulator явно обещает изоляцию
сценариев. Ингредиенты имеют историю, единицы и заметные действия. Help действительно
доступен крупным текстом EN/RU, с оглавлением и печатью. В Add ingredient проверен
пустой submit: «Enter a name.» возле Name, фокус на Name, `aria-invalid=true` и
`aria-describedby` на ошибку. Это нужно сохранить, а не заменить декоративной формой.

## Основные проблемы

1. **Одинаковая сила блоков.** Четыре сводные карточки Dashboard имеют равную площадь;
   сумма −€273.38 выглядит равной по смыслу счётчику «1 dish without volume».
2. **Слишком поздно появляется блюдо.** На 375 px сводки занимают почти весь экран
   после заголовка и периода. Причина и следующий шаг оказываются ниже.
3. **Редактирование далеко от сравнения.** Simulator сначала показывает пять карточек
   Baseline, общий объём, длинную таблицу, затем редактор сценария. Связь изменения
   с результатом требует прокрутки.
4. **Повторение рамок и подписей.** Recipe editor повторяет отдельную панель на каждую
   строку, а итог не виден рядом. Ingredients даёт New price / History / Rename / Delete
   почти одинаковый визуальный вес во всех строках.
5. **Недостаточно устойчивый размер контролов.** В текущем input `h-9` (36 px), на desktop
   `text-sm`; длинные обязательные подписи таблицы часто переносятся по 4–5 строк.
   Увеличение целей и структурное группирование лучше простого увеличения всего UI.

## Detector и ограничения

Реальная команда `impeccable detect --json src/ui src/components` завершилась **exit 2**:
один warning `side-tab` в `src/ui/help/HelpBlocks.tsx:121`, snippet `border-l-4`.
Это находка, не сбой инструмента. JSON сохранён в evidence/incumbent-detect.json.
Она касается стилистики callout, не доказывает проблему понимания текста; при
реализации заменить оформлением по токенам, сохранив семантику предупреждения.

Независимость оценок не обеспечена; baseline/current code commit vs deployment SHA
не сверялись. Не проверялись все комбинации клавиатуры, все ошибки, VoiceOver и
production-подпуть новой реализации — её пока нет. Первый снимок Help показывал
loading; он отброшен, после загрузки выполнен и просмотрен повторный снимок.
