# 06. План: локальная версия MenuPilot (D) и работа через кодового агента

Статус: **утверждён владельцем 2026-10-21** (версия после критики Sol `thr_4gc7ry22ag`).
Решения владельца: (1) изменения, предложенные агентом, **подтверждаются в окне MenuPilot**, а не в чате; (2) **урезанная первая версия**: macOS и Linux; из команд записи через CLI — только «добавить цену»; Windows и остальной CRUD — следующими шагами.
Основа: дорожная карта (браузер → D → C), критика Sol (`thr_4n3u6nd4mq`, `thr_4gc7ry22ag`), решение по сохранности данных (RPO, `thr_4gzudnq6h9`), шаг 2 (StorageAdapter, ревизии).

## 1. Что получает пользователь

```sh
git clone https://github.com/GadzhaProd/menupilot.git
cd menupilot
npm ci
npm start          # собирает интерфейс при необходимости и печатает адрес http://127.0.0.1:4710
```

- Тот же интерфейс MenuPilot; данные — в базе на компьютере, в папке вне checkout.
- Работа через агента: в папке проекта Claude Code / Codex; вопросы — сразу из команд MenuPilot; изменения агент только **предлагает**, владелец **подтверждает в окне MenuPilot**.
- Обновление: `git pull && npm ci && npm start`; данные не трогаются. Старая версия программы отказывается открывать базу нового формата.
- Перенос из браузерной версии: Export на сайте → Import в локальной версии с предпросмотром; после переноса версии независимы (без неявного объединения), исходный файл сохраняется.
- `npm run menupilot -- doctor`: версия Node, права и место в папке данных, занятый порт, формат базы, состояние копий.

Требования: проверенный patch-релиз Node 24 LTS (фиксируется в `engines` и проверяется при старте; встроенный `node:sqlite` с `backup()`, SQLite с исправлением WAL-reset), Git, macOS или Linux. Браузерная версия на GitHub Pages не меняется.

## 2. Архитектура

```
 Браузер (тот же UI)                 CLI / агент
        │ HTTP 127.0.0.1 + токен            │ HTTP к серверу (сервер обязан быть запущен)
        ▼                                   ▼
 ┌────────────── Локальный сервер MenuPilot — ЕДИНСТВЕННЫЙ писатель ──────────────┐
 │ HTTP API + раздача dist │ общий store: валидация, правила переходов │ src/calc  │
 │                     SqliteStorage (StorageAdapter на сервере)                 │
 └──────────────────────────────────┬────────────────────────────────────────────┘
                                    ▼
   Папка данных вне checkout (macOS ~/Library/Application Support/MenuPilot,
   Linux $XDG_DATA_HOME/menupilot или ~/.local/share/menupilot; MENUPILOT_DATA_DIR):
   menupilot.db (+ WAL), backups/, lock, token, logs/
```

- **Единственный писатель — только сервер.** Lock создаётся атомарно и содержит идентификатор экземпляра; освобождение — только своим экземпляром; живой процесс не вытесняется по таймауту; второй сервер не открывает базу на запись и сообщает адрес первого. Канонический путь папки данных. CLI без сервера — понятная ошибка «запустите npm start».
- **SQLite:** WAL + `synchronous=FULL`, `busy_timeout`, политика checkpoint; своя версия структуры БД (отдельно от `schemaVersion` документа). Таблицы: `meta`, `document` (модель «один документ»), `history`, `ops` (квитанции), `journal`, `plans`. Бюджеты размера для `history/ops/journal/plans`, обработка заполненного диска. Живую базу нельзя размещать в облачной/сетевой папке (проверка `doctor`).
- **Транзакция записи:** проверить `documentId` **и** `revision` → проверить опId (повтор с тем же содержимым → прежняя квитанция; с другим содержимым → отказ) → валидировать документ → **проверить допустимость перехода** (история цен только дописывается, смена единиц и другие правила команд; импорт/восстановление — отдельные явно разрешённые замены) → записать → +1 ревизия → журнал (источник ui/cli/agent) → квитанция. Контракт уточняется: квитанция хранит первоначальный результат операции, отдельно — текущая ревизия.
- **UI:** `HttpStorageAdapter` реализует существующий `StorageAdapter`: `beforeReplace`, защита черновиков, ограниченные повторы с прежним `opId`, `subscribe` (уведомления о чужих изменениях), поведение при перезапуске сервера. При ошибке локального конфига — понятная ошибка, **никогда** не тихий переход на браузерное хранилище. Конфиг (режим, токен) вставляется в HTML с безопасным экранированием (включая `</script>`), HTML с токеном не кешируется; отдаются только файлы сборки.

## 3. Безопасность сервера
- Только `127.0.0.1`; проверка `Host` (защита от DNS rebinding); проверка `Origin` для изменений; токен сеанса обязателен для **всего** API (включая чтение); отдельное правило для CLI (нет/`null` Origin + токен из файла с правами 0600).
- Без CORS, без изменений через GET, только JSON, лимит тела (согласован с лимитом сериализации в байтах UTF-8), таймауты, белый список маршрутов, CSP, запрет встраивания страницы (frame-ancestors), секреты и содержимое документов не попадают в логи; ротация логов.
- **Честная граница:** защищает от сторонних сайтов в браузере. Не защищает от расширения браузера с доступом к странице или от другого процесса того же пользователя на компьютере — это зафиксировано в README.

## 4. Сохранность данных (RPO)
- Признак «есть несохранённые в копию изменения» хранится в базе; снимок через `backup()` не позже 5 минут после изменения и при остановке/запуске (если прошлая сессия не успела) — хранить сутки; 14 ежедневных; видимая просрочка копирования.
- Копия перед импортом/восстановлением/миграцией соответствует состоянию **непосредственно перед** операцией (под тем же замком писателя, без чужих записей между копией и заменой); копия публикуется только после завершения и проверки; связь копии с ревизией записывается.
- Внешняя папка (`MENUPILOT_BACKUP_DIR`) — только готовые копии; при недоступности — повтор и предупреждение; честный текст: запись в облачную папку не доказывает синхронизацию.
- `backup verify` (restore-тест во временную базу), `backup restore` (новая ревизия с подтверждением); физическая подмена базы — отдельный аварийный протокол в `doctor`.

## 5. CLI, агент и подтверждение владельцем
- Вызов: `npm run menupilot -- <команда>` (+ бинарь `menupilot`). `--json` с `apiVersion: 1`, кодами ошибок, `documentId`, ревизией; деньги/BigInt — десятичными строками; все суммы и проценты считает только MenuPilot.
- **Чтение:** `status`, `doctor`, `what-changed [--since 30d|дата]`, `dishes`, `dish <id|точное имя>`, `ingredients`, `ingredient <id|точное имя>`, `preps`, `simulate …` (ничего не пишет), `history`, `backups`, `journal`.
- **Запись в первой версии — только `add-price`:** `propose add-price --ingredient <id|точное имя> --pack-price 18,00 --pack-size 1 kg` → сервер создаёт **план** (documentId, ревизия, версия протокола, точные ID, нормализованные значения, зафиксированные создаваемые ID/время, описание последствий: себестоимость затронутых блюд, месячный эффект) со сроком жизни (например 24 ч) и очисткой.
- **Подтверждение — в окне MenuPilot:** план появляется в интерфейсе («Ожидает вашего подтверждения» с последствиями); владелец нажимает «Применить» или «Отклонить». Применение плана, квитанция и отметка исполнения — одна транзакция; если данные изменились — план устарел. Агент видит статус через `plan status <id>`, но применить не может: API применения доступен только интерфейсу (отдельный признак сеанса UI), не CLI-токену.
- **Неоднозначность — отказ с кандидатами:** имена (без fuzzy-поиска для записи), единицы, упаковка, десятичная запятая, дата; цены — «без НДС, как в счёте» явно.
- **Агент:** раздел в AGENTS.md + `docs/agent/` (рецепты частых вопросов): числа только из команд; не считать самому; не трогать файлы данных; изменения только через `propose` и подтверждение владельца в окне MenuPilot. Честная формулировка: это защищает от ошибок и делает решение владельца обязательным шагом; от процесса с полными правами пользователя изоляции нет.

## 6. Этапы (ветка, тесты, независимое ревью и браузерная проверка на каждом)

| # | Этап | Исполнитель | Ревью |
|---|---|---|---|
| D1 | Протокол записи, SQLite, lock единственного писателя, идентичность/ревизии/квитанции, серверная проверка переходов, минимальная безопасность (127.0.0.1, Host, токен), затем `HttpStorageAdapter` и UI в локальном режиме; первые e2e | Astra | Sonnet |
| D2 | Полная безопасность (Origin, CSP, лимиты, логи) + независимые проверки безопасности и конкурентности (реальные дочерние процессы, потерянный ответ после commit) | Astra | Sol |
| D3 | Копии, восстановление, миграции, испытания отказов (заполненный диск, прерванный backup) | Astra (дизайн и ядро) + Luna (тесты, части) | Sol |
| D4 | CLI чтения, `doctor`, стабильный JSON | Luna | Sonnet |
| D5 | `propose add-price` + очередь планов + подтверждение в окне MenuPilot | Astra | Sonnet |
| D6 | Установка/обновление/остановка, AGENTS.md и docs/agent, README «Run locally / Use with an AI agent», итоговая приёмка | Sonnet (тексты) + Luna (e2e) | Sol |

Оценка: **8–10 рабочих дней** для урезанной версии (Sol: 12–18 для полной). После D — повторный аудит Sol.

## 7. Тесты
- Один контрактный набор `StorageAdapter` (браузер, SQLite, HTTP) с асинхронными fixtures и закрытием ресурсов.
- Конкурентность и сбои: два сервера, UI+CLI одновременно, потерянный ответ после commit, повтор после перезапуска сервера, прерывание процесса посреди записи, заполненный диск, прерванный backup, обновление при открытых черновиках (SIGKILL — не замена испытанию потери питания; это честно отмечается).
- Безопасность (раздел 3), restore-тест копий, «золотые» ответы CLI `--json`, e2e Playwright против локального сервера, мутационные проверки ключевых мест.

## 8. Следующие шаги после первой версии
Windows (ACL вместо 0600, пути с пробелами/Unicode, сигналы, блокировки файлов, `%LOCALAPPDATA%`); остальные команды записи через планы; облако C (общий протокол идентичности, ревизий, ошибок и повторов сохраняется; локальный токен не становится моделью авторизации облака).
